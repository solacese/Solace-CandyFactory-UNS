What is a Unified Namespace?

A Unified Namespace (UNS) is a single, real-time, hierarchically structured source of truth for everything happening across a business — from the shop floor to the top floor. Every system publishes its state to a common topic tree and subscribes to whatever it needs, instead of wiring brittle point-to-point integrations between each pair of systems.

What you're watching in this demo

This kiosk simulates a HARIBO-style candy factory as an event-driven UNS. A customer order flows all the way down to the packing robot and back up as completion status — and every step is a message on the namespace, visible live in the event feed on the right of the demo.

candyfactory/ ├─ enterprise/ │ ├─ orders/ L5 — customer orders │ └─ erp/ L4 — work orders, inventory └─ paris/ ├─ mes/ L3 — production, OEE └─ packing/line1/ ├─ scada/ L2 — sensors, conveyor ├─ arm/ L1 — pick-and-place robot └─ hitl/ human-in-the-loop approvals

The hierarchy follows the ISA-95 model (levels 0–5), a widely used standard for structuring manufacturing operations from field devices up to business planning. A well-formed topic tree is what makes a namespace "unified."

Why teams adopt a UNS

Decoupling

Producers and consumers never know about each other — they only share the namespace. Add a dashboard, an AI model, or a new line without touching existing systems.

Real-time by default

State is pushed the instant it changes. No polling, no nightly batch — the whole enterprise sees the same live picture.

Single source of truth

One consistently-structured tree means IT and OT finally speak the same language, with context (site, line, asset) baked into every topic.

Scales across sites

With an event mesh, the same namespace spans factories, clouds, and regions — events flow to wherever they're needed, securely.
